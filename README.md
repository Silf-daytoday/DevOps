# ЛР1 — Учёт успеваемости студентов (Вариант 8 (правка студента 2))

Команда из 2 человек. Приложение: Flask + SQLite (реляционная БД), HTTP API + веб-интерфейс.

## Быстрый старт (для тупых, по шагам)
1. Установи Python 3.10+.
2. `pip install -r requirements.txt`
3. Скопируй настройки: Windows — `copy .env.example .env`, Linux/Mac — `cp .env.example .env`
4. Запусти: `python app.py`
5. Открой в браузере: http://localhost:5000/ — там кнопки и формы.
6. Проверка: `python check.py` — должно быть «все проверки прошли».

Переменные окружения (файл `.env`, в git НЕ кладём!): `DATABASE_PATH`, `PORT`, `APP_VERSION`.

## Что где лежит
- `app.py` — ВЕСЬ код (чтобы легко объяснить). API + страницы + бизнес-правило.
- `schema.sql` — схема БД (5 таблиц, связи).
- `check.py` — локальные проверки (`make test` делает то же самое).
- `Makefile` — команды: `make setup`, `make run`, `make test`, `make verify`.
- `docs/` — ТЗ, описание API, правила изменений, деление на двоих, git-процесс.
- `.env.example` — пример настроек без секретов. `.env` — твои реальные настройки (не коммитить!).

## Сущности (вариант 8)
`groups` → `students`, `disciplines`, `study_plans` (что группа учит в семестре), `grades`.
Главное правило: оценку можно поставить, только если дисциплина есть в учебном плане группы студента на этот семестр, и оценка 2–5. Проверяет функция `check_business_rule` в `app.py`.

## Правила изменений (коротко, полное — в docs/RULES.md)
- Любая фича = задача → ветка → 2–3 коммита → Pull Request → проверка → merge.
- Перед коммитом: `python check.py`. Сломанное не пушим.
- Запрещено: коммитить `.env` и `*.db`, удалять проверки, пушить в `main` напрямую.
