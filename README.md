# Учёт успеваемости студентов — вариант 8

Flask, PostgreSQL 16, HTTP API и веб-интерфейс. ЛР2: запуск на двух Ubuntu Server
без GUI и контейнеров, приложение под отдельным пользователем через systemd.
Версия приложения — `0.2.0`.

Проектная команда из двух человек; техническая часть ЛР2 выполняется одним человеком
на одном Windows-компьютере с двумя ВМ VMware. История ЛР1 с SQLite сохранена в Git,
включая тег `v0.1.0`. Текущая ветка использует только PostgreSQL.

## Начало работы

Адреса 192.0.2.x — примеры для документации. Замените их адресами своего стенда.
Реальные адреса и секреты задаются во внешней конфигурации.

Полная инструкция для уже настроенных серверов, отдельной тестовой базы и защиты:
[docs/LR2.md](docs/LR2.md).

- Windows: `192.0.2.1`.
- app-server: `192.0.2.10`, приложение: http://192.0.2.10:5000/
- db-server: `192.0.2.20:5432`, доступ к БД только с app-server.
- Установка зависимостей: `python -m pip install -r requirements.txt` в venv.
- Сначала администратор применяет PostgreSQL-схему и права.
- `flask --app app init-admin` создает только начального admin, не таблицы.
- Для службы: `sudo bash deploy/install-app.sh`, заполнение внешнего env,
  затем `sudo systemctl enable --now devops-app`.
- Для локальной разработки с настроенной доступной PostgreSQL можно экспортировать
  переменные в своей оболочке и выполнить `python app.py`. Flask dev-server не
  используется для установленного сервиса; Gunicorn запускается в Linux.

Конфигурация: `DB_HOST`, `APP_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `PORT`,
`APP_VERSION`, `SECRET_KEY`, `ADMIN_PASSWORD`. Пример без секретов — [.env.example](.env.example).
Копирование .env само по себе не загружает переменные; служба использует
`EnvironmentFile=/etc/devops/app.env`. ADMIN_PASSWORD применяется только при первом
создании admin и не сбрасывает его существующий пароль.

## Структура

- `app.py` — API, веб-интерфейс, бизнес-правило, PostgreSQL-соединение, init-admin.
- `schema.sql` — шесть таблиц PostgreSQL со связями и ограничениями.
- `check.py` — существующие проверки ЛР1, адаптированные к отдельной devops_test.
- `Makefile` — setup, run, test, verify.
- `deploy/` — SQL подготовки БД, systemd-unit, ручной скрипт установки.
- `docs/LR2.md` — повторяемые команды и проверки защиты.
- `docs/TZ.md`, `docs/API.md`, `docs/RULES.md` — ТЗ, API, Git-процесс.

## Сущности и правило

`groups` → `students`, `disciplines`, `study_plans`, `grades`, `users`.
Оценку 2–5 можно поставить только если дисциплина включена в учебный план группы
студента на указанный семестр. Есть регистрация/вход, хранение хешей паролей,
ограничение изменения данных через веб-формы для неавторизованных пользователей.
Существующее поведение API сохранено.

## Проверки и Git

`make verify` запускает check.py и синтаксическую проверку. Нужны PostgreSQL,
`DB_NAME=devops_test`, `DB_USER=devops_test` и остальные параметры подключения.
Проверки очищают только эту специальную базу после проверки фактического соединения.
Запуск на основной devops запрещен до подключения. Команды — в docs/LR2.md.

GitFlow: задача → feature/* от develop → осмысленные коммиты → PR в develop →
проверка развертывания → release/0.2.0 → PR в main и обратное слияние в develop →
тег v0.2.0 на принятом коммите main после приемки. Релизная версия — 0.2.0.
Правила — [docs/RULES.md](docs/RULES.md). CI/CD в ЛР2 не добавляется.
