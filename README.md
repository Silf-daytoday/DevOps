# Учёт успеваемости студентов — вариант 8

**Версия проекта: 0.4.0**

Веб-приложение для учёта успеваемости студентов на базе Flask и PostgreSQL. Проект включает веб-интерфейс, HTTP API, систему миграций базы данных и контейнеризированное развёртывание.

В рамках ЛР4 реализована контейнеризация приложения и PostgreSQL с использованием Docker и Docker Compose.

## Технологический стек

- Python 3.12
- Flask
- Gunicorn
- PostgreSQL 16
- Alembic
- Docker
- Docker Compose
- Pytest
- Ruff
- Bandit
- Git

## Архитектура проекта

Система развёртывается на двух Ubuntu Server без графического интерфейса.

| Сервер | Назначение | Адрес |
|---|---|---|
| APP-сервер | Flask-приложение в Docker | 192.168.40.135 |
| DB-сервер | PostgreSQL в Docker | 192.168.40.136 |

Приложение доступно по адресу:

`http://192.168.40.135:5000`

PostgreSQL принимает подключения на порту 5432.

### Контейнеры

**APP-контейнер:**
- Сборка на основе Python 3.12 Slim.
- Запуск через Gunicorn.
- Два рабочих процесса.
- Непривилегированный пользователь UID 10001.
- Read-only файловая система.
- Ограничения CPU, памяти и количества процессов.
- Отключение Linux capabilities.
- Передача секретов через Docker Secrets.
- Проверка работоспособности через HTTP endpoint `/health`.

**DB-контейнер:**
- PostgreSQL 16.15.
- Постоянное хранение данных через Docker Volume.
- Проверка готовности через `pg_isready`.
- Ограничения CPU, памяти и количества процессов.
- Передача паролей через Docker Secrets.

## Безопасность

В проекте реализованы следующие меры:

- Запрет запуска приложения от root.
- Использование Docker Secrets для передачи паролей и ключей.
- Исключение секретов из Git и Docker build context.
- Запрет привилегированного режима контейнеров.
- `no-new-privileges`.
- Ограничение доступных контейнеру возможностей через `cap_drop: ALL`.
- Read-only файловая система приложения.
- Ограничения ресурсов контейнеров.
- Фиксированные версии Docker-образов вместо `latest`.

Секреты хранятся локально в каталоге `secrets/` и не включаются в Git.

## Развёртывание

Для развёртывания необходимы:
- Ubuntu Server.
- Docker Engine.
- Docker Compose Plugin.
- Доступ APP-сервера к DB-серверу по порту 5432.
- Подготовленные файлы секретов.

### 1. Развёртывание PostgreSQL

На DB-сервере необходимо подготовить секреты:

- `secrets/postgres_password.txt`
- `secrets/db_password.txt`

После подготовки файлов из корневого каталога проекта запускается:

```bash
sudo docker compose -f compose.db.yaml up -d
```

Проверка состояния:

```bash
sudo docker compose -f compose.db.yaml ps
```

### 2. Развёртывание приложения

На APP-сервере необходимо подготовить секреты:

- `secrets/db_password.txt`
- `secrets/secret_key.txt`
- `secrets/admin_password.txt`

Сборка и запуск:

```bash
sudo docker compose -f compose.app.yaml up -d --build
```

Проверка состояния:

```bash
sudo docker compose -f compose.app.yaml ps
```

### 3. Проверка приложения

Проверка доступности приложения:

```bash
curl -i http://192.168.40.135:5000/health
```

Ожидаемый ответ:

```json
{"status":"ok"}
```

Проверка версии:

```bash
curl http://192.168.40.135:5000/version
```

## Хранение и восстановление данных

Для PostgreSQL используется именованный Docker Volume `postgres_data`.

Данные сохраняются при остановке и пересоздании контейнера.

Для резервного копирования используется PostgreSQL `pg_dump` в формате Custom.

Восстановление выполняется с помощью `pg_restore`.

В рамках ЛР4 проверено:
- Создание резервной копии.
- Проверка содержимого архива.
- Восстановление в отдельный PostgreSQL-контейнер.
- Восстановление в новый Docker Volume.
- Сравнение количества записей в восстановленной и рабочей базах данных.

## Проверки проекта

Для управления проверками используется Makefile.

| Команда | Назначение |
|---|---|
| `make setup` | Подготовка виртуального окружения |
| `make quality` | Ruff и Bandit |
| `make test` | Запуск автоматических тестов |
| `make migration-check` | Проверка миграций |
| `make backup-check` | Проверка резервного копирования и восстановления |
| `make mutation` | Проверка контролируемых мутаций |
| `make container-check` | Проверка конфигурации контейнеризации |
| `make verify` | Последовательный запуск полного набора проверок |

### Результаты проверки контейнеризации

Команда `make container-check` проверяет:
- Наличие необходимых файлов.
- Непривилегированного пользователя приложения.
- Healthcheck.
- Ограничения ресурсов.
- Docker Secrets.
- Постоянное хранение данных PostgreSQL.
- Настройки безопасности контейнеров.
- Исключение секретов из Git и Docker build context.
- Синтаксис Docker Compose при наличии Docker CLI.

## Git и порядок приёмки

Разработка ведётся в отдельных feature-ветках.

Изменения принимаются через Pull Request в `develop`.

Для выпуска версии создаётся release-ветка, выполняется повторная проверка `verify`, после чего создаётся Pull Request в `main`.

Прямой push в `main`, force push и переписывание опубликованной истории запрещены.
