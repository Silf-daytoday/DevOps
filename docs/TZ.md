# Техническое задание (ЛР1, Вариант 8) — кратко по ГОСТ

## 1. Назначение
Система «Учёт успеваемости»: хранить студентов, группы, дисциплины, учебные планы и оценки; считать средний балл; не давать ставить липовые оценки.

## 2. Пользователи
- **Методист**: ведёт группы, студентов, дисциплины, учебные планы, оценки.
- **Преподаватель**: ставит оценки, смотрит отчёты.
- **Студент** (только чтение): смотрит свои оценки через веб-страницу.
- Все, кто изменяет данные, проходят аутентификацию (регистрация и вход
по логину и паролю, таблица `users`). Пароли хранятся только в виде хеша.

## 3. Сценарии
1. Создать группу → добавить студентов → создать дисциплины → связать в учебном плане → поставить оценки → посмотреть средний балл.
2. Попытка поставить оценку без учебного плана → система отказывает с понятной ошибкой.
3. Открыть `/health` — убедиться, что всё живо.

## 4. Функции
- CRUD: группы, студенты, дисциплины, учебные планы, оценки (через API и веб-формы).
- Аутентификация: регистрация, вход, выход (веб и API), текущий пользователь.
- Отчёт `GET /api/report/avg` — средний балл по каждому студенту.
- Служебные: `GET /health`, `GET /version`, `GET /api/docs`.

## 5. Сущности и связи
- `groups(id, name UNIQUE, year)` — 1 группа : N студентов.
- `students(id, fio, group_id→groups, student_no UNIQUE)`.
- `disciplines(id, name UNIQUE, credits)`.
- `study_plans(id, group_id→groups, discipline_id→disciplines, semester)` UNIQUE(группа, дисциплина, семестр).
- `grades(id, student_id→students, discipline_id→disciplines, semester, value 2–5)` UNIQUE(студент, дисциплина, семестр).
- `users(id, username UNIQUE, password_hash, role)` — учётные записи; хранится хеш пароля.

## 6. Ограничения и правила
- **П1 (главное):** оценка ставится, только если (группа студента + дисциплина + семестр) есть в `study_plans`.
- **П2:** оценка ∈ {2,3,4,5}.
- **П3:** номер зачётки уникален; одна оценка на связку (студент, дисциплина, семестр).
- Ошибки: неверные данные → 400 + JSON `{"error": "..."}`; нет ресурса → 404.

## 7. Хранение и конфиг
- СУБД: SQLite (реляционная, файл `data/app.db`), связи через FOREIGN KEY.
- Настройки только через env: `DATABASE_PATH`, `PORT`, `APP_VERSION`, `SECRET_KEY`,
`ADMIN_PASSWORD`. Секреты в `.env`, который в git не входит.
- Изменение данных через веб-формы доступно только после входа.
