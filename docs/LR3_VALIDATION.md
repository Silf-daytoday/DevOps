## Выполнено в среде подготовки

Окружение: Debian 13, Python 3.12.14, отдельный нативный PostgreSQL **16.11**.
PostgreSQL собран из официального исходного архива 16.11, использованы его
настоящие pg_dump/pg_restore. Тестовая роль devops_test — LOGIN,
без SUPERUSER/CREATEDB/CREATEROLE, с паролем и SCRAM для TCP.
Это не эмуляция БД и не замена PostgreSQL SQLite/PGlite.

Успешно:
- SQL подготовки четырёх тестовых БД: первый запуск и повторный запуск успешны.
- make setup, установка закреплённых зависимостей в Python venv, pip check.
- make verify: **137 passed**, **99,09%** общего покрытия app/domain,
  порог 70% выполнен.
- Ruff formatter --check и Ruff check — без нарушений.
- Bandit — без обнаруженных проблем; четыре узких исключения B404/B603
  для проверенных subprocess объяснены в docs/LR3.md и исходниках.
- Миграции на чистой БД до 004_grade_created_at.
- Заполненная схема ЛР2 без version table: проверенный baseline,
  сохранение оценок, NULL для старых дат, downgrade/upgrade тестовой схемы.
- Отказ baseline при дополнительном столбце или изменённом DEFAULT.
- Настоящий pg_dump, повреждение названия/оценки/комментария, pg_restore,
  точное сравнение шести таблиц и вставка после восстановления (identity).
- Два контрольных мутанта обнаружены конкретными unit-тестами.
- Старый check.py: все проверки ЛР2 прошли на новой схеме/приложении.
- bash -n трёх shell-скриптов, git diff --check — успешно.
