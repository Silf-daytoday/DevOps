# ЛР2: результаты проверки

Дата: 16.10.2026. Исходная версия — main 71f1cd8.
Версия разработки — 0.2.0-dev.

## Изменения

- Приложение перенесено на Psycopg 3 и PostgreSQL без изменения предметной области.
- Схема из 6 таблиц применяется администратором от имени devops_owner.
- devops_app получает SELECT/INSERT на таблицы и USAGE на последовательности.
- init-admin создает начального администратора без DDL и без сброса пароля.
- check.py работает только с отдельной devops_test и проверяет фактическое соединение до очистки.
- Подготовлены systemd-unit, ручной скрипт установки, внешний env и docs/LR2.md.

## Проверено на целевом стенде

Пользователь выполнил make verify два раза подряд через SSH на app-server
с отдельной базой devops_test на ранее настроенном PostgreSQL 16 db-server.
Предоставленный 16.10.2026 вывод содержит успешное завершение первого запуска
и полный успешный второй запуск: «ИТОГ: все проверки прошли.» и «syntax OK».

Проверены API, веб-страница, регистрация/вход/выход, бизнес-правило оценки,
отклонение некорректных значений и дубликатов, rollback после ошибки БД,
числовой средний балл и порядок студентов без оценок.
Повторный init-admin сохраняет пароль существующей записи.
Код приложения и проверок между двумя запусками не менялся.

Это ручной запуск существующих проверок в целевой среде, не CI и не независимое
ревью второго участника.

### Установленное приложение и восстановление

По скриншотам пользователя подтверждены запуск Gunicorn через systemd,
успешный init-admin, прослушивание Host-only адреса, ответы /health 200 и
/version 0.2.0-dev. После настройки APP_HOST и отключения управляющего сокета
Gunicorn служба работает без прежних сообщений конфигурации.

После перезагрузки обеих ВМ предоставлены результаты: приложение active,
PostgreSQL 16/main online, UFW active на обоих узлах. На app-server разрешены
SSH и HTTP приложения с клиентского узла, на db-server — SSH с клиента и
PostgreSQL только с app-server. Пользователь подтвердил вход через браузер.

Пользователь также подтвердил успешное выполнение сценариев SIGKILL службы с
автоматическим восстановлением и остановки/запуска кластера БД с восстановлением
/health без ручного перезапуска приложения. Созданная через сайт группа
сохранилась после перезагрузки. Это результаты ручного выполнения пользователем.

## Проверено в среде подготовки

- Установка requirements.txt в отдельный Python 3.12 venv, pip check — успешно.
- Синтаксис app.py/check.py, bash -n deploy/install-app.sh, git diff --check — успешно.
- systemd-analyze verify — успешно в отдельном тестовом корне с заглушками
  исполняемых путей и базовыми targets. Это проверка структуры unit,
  не запуск службы и не проверка пользователя/прав на реальном сервере.
- check.py с DB_NAME=devops и DB_USER=devops_app отказывает до импорта и подключения.
- /version возвращает 0.2.0-dev без обращения к БД.
- /health при недоступном адресе БД возвращает 500 и status=fail,
  журнал содержит диагностическую причину без пароля.

## Заключительные проверки на виртуальных машинах

Пользователь подтвердил успешное выполнение всех трех заключительных пунктов:

- Параметр RestartSec изменен с 5s на 10s отдельным drop-in; после удаления
  только этого файла и daemon-reload/restart значение вернулось к 5s.
- Подключение TCP к порту PostgreSQL с Windows не прошло, а SELECT с app-server
  под devops_app одновременно успешен. Обе проверки привилегий CREATE вернули false.
- Процессы Gunicorn работают от devopsapp. Файл app.py принадлежит root:root и
  имеет права 644, venv — root:root 755, каталог /etc/devops — root:root 750,
  app.env — root:root 600.

По предоставленным скриншотам и сообщениям пользователя серверные проверки ЛР2
завершены. Прямого доступа помощника к ВМ не было: команды выполнял пользователь.
