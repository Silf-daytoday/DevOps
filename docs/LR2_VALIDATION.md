# ЛР2: результаты проверки

Дата: 16.10.2026. Исходная версия — main 71f1cd8.
Серверная приемка ниже выполнена на версии 0.2.0-dev; релизная версия — 0.2.0.

## Изменения

- Приложение перенесено на Psycopg 3 и PostgreSQL без изменения предметной области.
- Схема из 6 таблиц применяется администратором от имени devops_owner.
- devops_app получает SELECT/INSERT на таблицы и USAGE на последовательности.
- init-admin создает начального администратора без DDL и без сброса пароля.
- check.py работает только с отдельной devops_test и проверяет фактическое соединение до очистки.
- Подготовлены systemd-unit, ручной скрипт установки, внешний env и docs/LR2.md.

## Проверено на целевом стенде

Пользователь выполнил make verify два раза подряд через SSH на app-server
с отдельной базой devops_test на ранее настроенном PostgreSQL 16 db-server.

и полный успешный второй запуск: «ИТОГ: все проверки прошли.» и «syntax OK».

Проверены API, веб-страница, регистрация/вход/выход, бизнес-правило оценки,
отклонение некорректных значений и дубликатов, rollback после ошибки БД,

Это ручной запуск существующих проверок в целевой среде, не CI и не независимое
ревью второго участника.

## Приемка GitFlow

PR [#1](https://github.com/Silf-daytoday/DevOps/pull/1) из
feature/lr2-postgresql-linux слит в develop 16.10.2026, merge-коммит e96e2d4.
Ветка release/0.2.0 подготовлена от этого коммита. Изменены значение версии
по умолчанию, шаблон внешней конфигурации и документация; бизнес-логика,
SQL-схема, проверки и systemd-unit остались теми же.

Для релизной версии в среде подготовки успешно проверены синтаксис app.py/check.py,
git diff --check, ответ /version со значением 0.2.0 по умолчанию и приоритет
APP_VERSION из окружения. Эти проверки /version не требуют соединения с БД.

Перед публикацией release-ветки на целевом стенде повторяются make verify
с отдельной devops_test, затем /health и /version установленного приложения.
В /etc/devops/app.env также устанавливается APP_VERSION=0.2.0.
Эти результаты не подменяются предыдущими результатами версии 0.2.0-dev.
После приемки выполняются PR в main, обратное слияние в develop и тег v0.2.0
на принятом коммите main; старый v0.1.0 сохраняется.
