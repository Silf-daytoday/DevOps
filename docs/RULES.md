# Правила изменения и приёмки

1. Задача → feature-ветка от актуального develop → осмысленные коммиты →
   проверки → PR в develop. Карточка задачи связывается с PR.
2. Перед push ЛР3 обязателен полный успешный make verify на PostgreSQL 16:
   форматирование, линтер, SAST, тесты/покрытие, миграции, backup/restore,
   контролируемые мутации. check.py сохранён как дополнительная регрессия.
3. Запрещены пропуск/удаление тестов, снижение порога 70% покрытия кода,
   скрытие ненулевых кодов возврата и ослабление проверок ради публикации.
   Не менее 40% функций ТЗ подтверждаются отдельной матрицей.
4. Каждое исключение анализатора требует объяснения. Узкие nosec B404/B603
   относятся к штатным pg_dump/pg_restore и дочернему pytest без shell;
   разбор — docs/LR3.md.
5. Новая функция принимается после полного verify, просмотра diff
   и проверки браузера/health на ВМ. Критические app.py/domain.py,
   migrations, tests, Makefile, pyproject.toml и зависимости видны в PR.
6. Самостоятельная приёмка называется самостоятельной. Подготовленная
   инструкция и фактически выполненная проверка имеют разные статусы.
7. Проверки очищают только четыре выделенные тестовые БД от devops_test.
   Перед операциями проверяются выбранные и фактические база/роль.
8. Основную devops изменяет локальный postgres на DB после резервной копии.
   Runtime не получает DDL. Восстановление требует CONFIRM_RESTORE=имя_цели.
9. В Git запрещены реальные env, ключи, дампы, БД, venv и локальные отчёты.
   Пароли вводятся интерактивно и не попадают в сообщения коммитов.
10. Запрещены прямой push в main, force push и переписывание опубликованной
    истории. Коммиты оформляются от Silf-daytoday.
11. После приёмки: release/0.3.0 от develop, версия 0.3.0, повторный verify;
    PR в main и обратное слияние в develop. Тег v0.3.0 — на принятом main.
    Старые теги v0.1.0 и v0.2.0 не перемещаются.

12. Запрещено использовать тег latest для Docker-образов.
    Версии образов должны быть зафиксированы.

13. Запрещён запуск приложения от root.
    Контейнер приложения должен использовать непривилегированного пользователя.

14. Запрещено помещать пароли, ключи и другие секреты
    в Docker-образ, Dockerfile или build context.
    Для передачи секретов используются Docker Secrets.

15. Запрещено отключать healthcheck и публиковать
    ненужные порты контейнеров.
    Порт PostgreSQL разрешается публиковать только
    при необходимости сетевого доступа приложения.

16. Изменение контейнерного окружения разрешается
    только после успешного выполнения make container-check.
